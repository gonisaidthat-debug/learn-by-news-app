# learn-by-news-app 설계 문서

> 단일 출처는 두 개다. 앱 UI·구조는 이 문서, **서버 API 계약은 웹 리포의 `docs/design.md` 14장**(https://github.com/gonisaidthat-debug/learn-by-news/blob/main/docs/design.md). 아래는 그 14장의 사본(2026-11-06)이며 서버가 바뀌면 웹 리포 쪽이 먼저 바뀌고 여기로 복사한다.

## 0. 한 줄 요약

웹(https://learn-by-news.goni-said-that.workers.dev)과 같은 Worker API·D1을 쓰는 SwiftUI 네이티브 iOS 앱. 웹은 그대로 두고, 앱은 폰에서 번역 연습을 하기 위한 두 번째 클라이언트.

## 1. 결정된 것과 남은 것

**goni 결정 (2026-11-06):**
- 화면 범위: **전부**. 공책 목록(붙여넣기 포함), 공책(번역·채점·다시 쓰기·건너뛰기·제거·합치기), 마지막 장(점수·총평), 표현장(포스트잇 벽), 시험지, 기록, 공부 세션.
- 공책 UI: **웹과 같은 은유**. 줄노트 위 인쇄체 원문 + 손글씨 번역, 왼쪽 여백 등급 도장, 빨간 물결 밑줄, 연필 참고 번역, 포스트잇, "✂ 여기까지" 점선. 글꼴은 Nanum Pen Script(OFL)를 앱에 번들.

**goni 추가 결정 (2026-11-06): 나머지도 전부 웹과 동일하게.** 비밀번호는 한 번 입력해 Keychain에 두고(웹의 localStorage 역할), 세션 시작점은 UserDefaults(웹의 localStorage 역할), 붙여넣기는 텍스트 붙여넣기 칸 + 링크 칸(웹과 같은 자동 URL 감지). 공유 시트는 나중.

**goni 추가 결정 (2026-11-06): 버그 추적용 로그 기능 포함.** 앱은 OSLog와 로컬 순환 파일(최근 2000줄)에 기록한다. 설정 화면의 "로그 보내기"와, 다음 실행 시 자동(직전 실행에 error/fatal이 있었거나 비정상 종료였으면)으로 서버 `POST /api/logs`에 올린다. 항목: level(debug/info/warn/error/fatal), tag(화면/모듈), message, context(JSON), at. 기사 원문·번역 전문은 넣지 않는다(문장 id만). 서버는 30일 보관하고 웹 세션에서 `GET /api/logs`로 본다. 설정 화면에 로컬 로그 보기·지우기도 둔다.

**앱 세션에서 goni와 정할 것 (남은 것 없음, 구현하며 생기면 여기에):**
- 세션 시작점(UserDefaults)과 비밀번호 보관(Keychain).
- 기사 붙여넣기 경로: 클립보드 붙여넣기 + 공유 시트(URL만 올 수 있음).

## 2. API 계약 (웹 리포 14장 사본, 2026-11-06)

결정: **웹은 그대로 두고, iOS 앱을 SwiftUI 네이티브로 따로 만든다. DB는 공유한다.** 공유 방법은 앱이 웹과 같은 Worker API를 호출하는 것. 별도 리포 `learn-by-news-app`, 별도 세션. 이 절이 그 세션의 단일 출처다. 서버가 바뀌면 이 절도 같이 고친다.

### 기본
- Base URL: `https://learn-by-news.goni-said-that.workers.dev`
- 모든 요청: `Authorization: Bearer <percent-encoded UTF-8 APP_PASSWORD>` (헤더는 ASCII만 실리므로 한글 비밀번호는 반드시 인코딩. Swift: `addingPercentEncoding(withAllowedCharacters: .alphanumerics)`). 서버는 디코드해 비교하며 인코딩 안 된 ASCII 값도 받는다. 비밀번호 입력란은 한글 키보드를 막지 않는다. JSON 본문은 `Content-Type: application/json`. 틀리면 `401 {"error":"unauthorized"}`.
- 오류는 항상 `{"error": "<한국어 메시지>"}`. 429는 하루 Claude 호출 상한. 413은 본문 512KB 초과.
- 시각은 전부 Unix ms. 등급은 `"A"|"B"|"C"|"D"|"skip"`. 점수는 등급 평균(A100 B80 C50 D20, skip 제외, 반올림)이며 **클라이언트가 계산**한다.
- 앱 아이콘 초안: `docs/assets/app-icon-1024.png` (공책+도장, 자체 제작).

### 타입
```
Feedback   { grade, issues: [{source, mine, meaning, why}], reference, expressions: [{phrase, meaning}] }
Attempt    { translation, grade, feedback: Feedback, created_at }
Sentence   { id, idx, paragraph, text, attempt: Attempt|null, history: Attempt[] }   // history = 이전 시도, 오래된 순
Phrase     { id, phrase, meaning, sentence_id, article_id, created_at, sentence_text?, article_title? }
Review     { id, score: int|null, created_at, summary, patterns: [{title, detail}], praise }
Session    { id, started_at, ended_at, attempts, score: int|null, articles: string[], created_at }
Highlight  { id, sentence_id, article_id, start_word, end_word, span, answer: {meaning, why, similar}, note: string|null, created_at }
Drill      { id, phrase_id, phrase, meaning, korean, created_at, kind: "prompt"|"free", sentence_id, answer, grade, feedback: {grade, used_expression, issues[{mine, better, why}], reference, reference_ko, note}|null, answered_at, reference? }
QuizItem   { key, kind: "issue"|"phrase"|"highlight", sentence_id, article_id, article_title, sentence_idx, sentence_text,
             source, mine, meaning, why, issued_at, last_correct: bool|null, last_at, tries, wrong }
```

### 클라이언트가 지켜야 할 규칙 (웹과 동일 동작)
- **문장 분리**는 클라이언트 몫. 첫 줄 제목, URL만 있는 줄은 source, 빈 줄 사이가 문단. 약어(월 약어, Mr./Dr./Jr., No., vs., U.S. 등) 뒤는 끊지 않고, 소문자·구두점으로 시작하는 조각은 앞에 붙인다. iOS는 `NLTokenizer(unit: .sentence)` + 같은 보정.
- **제출 즉시 다음 문장**으로 넘어가고 채점은 뒤에서 받는다(여러 개 동시 가능). 결과가 오면 그 문장을 펼쳐 보여준다.
- **멈추기**: 채점 중인 문장에 "멈추기 ↩". 누르면 요청을 취소(URLSessionTask.cancel)하고 `DELETE /api/attempts/:attempt_id`를 보낸 뒤, 그 문장이 다시 입력란이 되고 쓰던 번역이 그대로 들어간다(다시 쓰기 중이었으면 그 자리에서). 제출할 때 attempt_id를 UUID로 만들어 보내야 멈추기가 된다.
- **응용 채점 멈추기**(goni 2026-11-18, 웹 26a36a8): 응용 탭은 "선생님이 보는 중… ✎" 옆, 써 보기 상자는 "채점 중… ✎" 옆에 "멈추기 ↩". 누르면 요청 Task를 취소하고 `DELETE /api/drills/:id/grading`(출제형은 문제 id, 자유 작문은 제출 때 만든 클라이언트 UUID `drill_id`)을 보낸다(오프라인이면 큐 `drill_grading_cancel`). 쓰던 문장은 입력란에 그대로 남고 포커스, 문제는 안 푼 채로 남아 다시 제출할 수 있다. 늦게 온 결과·오류(409 cancelled, 취소)는 버린다. 자유 작문 큐(`drill_free`)에도 `drill_id`가 들어가 재전송이 중복 저장되지 않는다(`duplicate`). 큐에 있는 채점 대기 항목은 멈추기 버튼이 없다(기존 흐름 그대로).
- **닫은 뒤 총평은 한 번만**(goni 2026-11-18, 웹과 같은 규칙): 공책에서 "오늘 여기까지"를 누르면 본문의 "✂ 여기까지 · …" 줄 아래 총평이 붙는데, 같은 세션의 총평이 입력란 아래 "기록했다 · …" 줄에도 있었다. 닫힌 세션이 이 공책에 ✂ 줄을 만들고 총평이 있으면 아래 줄은 숨긴다(`SessionBar(reviewShownInBody:)`). 총평을 못 받았으면(review null) 아래 줄을 남겨 "다시 시도"를 누를 수 있게 하고, 다른 공책에서 닫은 세션(이 공책에 ✂ 줄 없음)이면 아래 줄 그대로.
- **습득 완료 도장**(goni 2026-11-18, 웹 6e8d2f6): 표현장 포스트잇 아래 왼쪽 "습득 완료 ✓" → `PUT /api/phrases/:id/mastered {on}`(캐시 `masteredAt` 먼저, 오프라인이면 큐 `phrase_mastered`). 찍히면 흐려지고(0.62) 오른쪽 아래 초록 테두리 "습득 완료" 도장(−12°), 버튼은 "다시 보기 ↻"(on:false). 검색창 아래 "N개 · 습득 완료 M개 · 습득 완료도 보기/숨기기"(도장이 하나라도 있을 때만, UserDefaults `lbn_phrases_show_mastered`, 기본 숨김). 공책·총평 화면의 포스트잇에도 같은 도장. ×(삭제)는 별개. 캐시 집계는 시험지에서 mastered를 뺀다(응용 로컬 출제는 서버 batch가 이미 뺀 것을 받는다). 증분 동기화는 created_at 기준이라 도장 변경이 안 오므로 로컬 반영 + 전체 동기화 때 맞춘다. `local-` 임시 표현은 서버에 붙기 전이라 도장을 거절한다.
- **포스트잇 떼기 = 습득 완료**(goni 2026-11-18, 웹 61d32b7): 공책·마지막 장에서 붙은 포스트잇을 다시 누르면 DELETE가 아니라 습득 완료 토글(`SyncManager.setMastered`, 오프라인이면 큐 `phrase_mastered`). 빨간 펜 지적의 "붙여 둠 ✓"도 같은 토글이고 찍히면 "습득 완료 ✓". 안 붙은 포스트잇은 전처럼 붙인다(POST). 표현을 지우는 건 표현장의 ×뿐. 계약 변경 없음.
- **채점 중 백그라운드**(goni 2026-11-18 "채점 중에 백그라운드로 가면 실패하는 것 같다"): 원인은 11/17 iPhone 로그 — 제출 9~10초 뒤 "The network connection was lost."(앱 정지로 연결 끊김) → 큐 → 재전송이 서버 UNIQUE 500으로 버려져 다시 써야 했다(서버는 11/17 저녁 멱등으로 고쳐 재전송이 duplicate 200). 앱 보강: ① 쓰기 요청(GET 제외) 동안 `UIApplication.beginBackgroundTask`(`BackgroundGuard`)로 약 30초 보호 — 짧게 나갔다 오면 요청이 살아 결과를 받는다. ② 멈추기가 아닌 취소(시스템)도 큐로. ③ 포그라운드 복귀 때 "채점 중"인데 요청 Task가 없으면 큐로(`recoverInflight`). ④ 써 보기 상자의 출제형 답도 네트워크 오류면 큐 `drill_answer`. 세션 닫기(POST sessions)도 같은 보호를 받고, 끊기면 전처럼 임시 세션 + 큐. goni가 보낸 11/15 09:33 스크린샷은 다른 일: 오프라인에서 쓴 두 문장이 큐에 있다가 온라인 복귀 직후 `PUT /api/session-start` 응답(`{started_at}`)을 앱이 `{ok}`로 기대해 해석 실패 → 거절로 오인해 시작점을 지움("공부 시작 ▶" 안내 + 빨간 "응답을 읽을 수 없습니다"), 10초 뒤 두 채점은 정상 전송·저장(09:33:47·49). 그 버그는 11/15 오후에 고쳤고, 이번에 응답 해석 실패를 `APIError.decode`로 분리해 서버 거절(`.server`)과 섞이지 않게 했다(로그에 DecodingError 상세 + 응답 앞 300자).

- **회차 열람**(공책 목록 카드의 "1회차 2회차 …" 링크, 진행 중이면 "n회차 진행 중"은 공책으로): 회차 = n번째 총평. 각 문장의 번역을 "그 총평 시각까지의 마지막 시도"로 바꿔 열람 화면에 보여준다(이전 시도도 그 시점까지만, 총평도 n번째까지). 탭 "n회차 열람". 클라이언트가 history(created_at)로 계산, 서버 변경 없음.
- **책갈피**(goni 요청 2026-11-10): 문장 항목의 메뉴(길게 누르기 또는 ⋯)에 "책갈피 꽂기/빼기". **펼쳐 본 문장은 자동으로 책갈피**(공책·열람·마지막 장에서 항목을 펼치면 0.5초 뒤 PUT, goni 결정 2026-11-10). 수동 메뉴는 그대로. 한 번에 하나. 꽂힌 문장은 오른쪽 위 빨간 리본. 회차 열람 중이면 round도 저장. 공책 목록 맨 위에 "🔖 책갈피 · 기사 · n번째 문장 · (회차)" 띠, 누르면 그 문장이 펼쳐진 열람 화면(회차 있으면 그 회차)으로. 띠의 ×로 뺌. 오프라인이면 캐시된 책갈피로 이동.
- **형광펜**(goni 결정 2026-11-10, "첫 단어·끝 단어 두 번 누르기"): 펼친 문장의 원문을 단어 조각(공백 분리, 인덱스 0부터)으로 그린다. 단어를 탭하면 노랗게, 다른 단어를 탭하면 그 사이가 한 덩어리로(앞 단어를 탭해도 됨). 말풍선 "이게 뭐야? 🖍" → `POST /api/sentences/:id/ask` → 문장 아래 노란 메모(구절 → 뜻 (이유) · 비슷한 말), 칠한 단어는 계속 노랗게. 응답의 phrase는 공책 phrases에 합쳐 포스트잇 "붙은" 상태로. 시험지에 "형광펜" 묶음(kind highlight, 🖍 도장). 오프라인에서는 묻기 불가("온라인에서만").
- **처음부터 다시 쓰기**(마지막 장 버튼): 첫 문장부터 순서대로 다시 쓰기 모드로 돈다(진행 표시 "다시 n / m"). **화면은 처음 하는 것처럼 비운다**: 이번에 새로 제출한 문장만 위에 쌓이고, 아직 안 쓴 문장(이전 번역·도장)은 보이지 않는다. 이전 번역은 데이터로 남아 펼치면 "이전 시도"로만 보인다(goni 결정 2026-11-10). **진행 상태는 기기에 저장**(UserDefaults, 공책별 ids·done)해 앱을 껐다 켜거나 다른 화면에 다녀와도 그 자리에서 이어진다. 마지막 장은 진행 중이면 "처음부터 다시 쓰기 이어서 (n / m) →"를 보여주고 총평을 자동 요청하지 않는다. 저장이 없을 때는 "최근 24시간 안에 다시 쓴 앞쪽 문장 수"로 추정해 "오늘 다시 쓴 n문장 다음부터 이어서 →"를 보여준다. 중단·완료 시 저장을 지운다. 각 제출은 새 attempt(이전 것은 history). 중간에 취소 가능. 마지막 문장을 제출하면 공책에 머물며 채점이 전부 끝나길 기다렸다가 마지막 장으로 가서 새 총평을 자동 요청한다(`POST /api/articles/:id/review`, 기존 총평은 그대로 남음). 채점 오류로 "다시 시도" 상태인 문장이 있으면 이동하지 않는다. **마지막 장은 받아 온 진행 상태(pass)가 공책의 모든 문장을 덮으면 끝난 회차의 찌꺼기로 보고 DELETE 후 평소대로(새 총평 자동 요청) 간다**(2026-11-23, 웹 6ebbc32와 같은 규칙). 앱: 마지막 문장 제출은 원래 DELETE만 보내고, `SyncManager.putPass/deletePass`는 같은 기사의 요청을 보낸 순서대로 하나씩 보낸다(앞 문장의 PUT이 늦게 도착해 DELETE를 덮지 않게). DELETE를 큐에 넣을 때 그 기사의 pass_put은 큐에서 뺀다(PUT도 마지막 하나만). PUT 응답 `finished:true`면 로컬 RedoProgress를 지운다. 마지막 장(`DoneModel.load`)·공책 목록 동기화(`Cache.applyServerPass`)는 모든 문장을 덮는 done을 진행 없음으로 본다(마지막 장은 DELETE도 보낸다). 모의 서버도 같은 응답.
- **세션 시작점은 클라이언트가 보관**(웹은 localStorage). 앱은 UserDefaults. 시작 전에는 입력 불가. "오늘 여기까지"는 `POST /api/sessions {started_at}`. 기기 간 시작점은 공유되지 않는다(필요해지면 서버로 옮긴다).
- 참고 번역 기본 펼침. 등급 도장·빨간 밑줄(issue.mine을 번역에서 찾아 표시)·포스트잇 저장 토글은 웹과 같은 의미.
- 폴백 금지: 채점 실패 시 같은 요청 재시도만.

### 시뮬레이터 확인용 환경변수 (DEBUG 빌드만)
- `SIMCTL_CHILD_LBN_MOCK=1`: 서버 대신 메모리 모의 서버(`MockServer`). 비밀번호 없이 화면을 볼 수 있다.
- `SIMCTL_CHILD_LBN_ROUTE=notebook:a1 | notebook:a1:s2 | done:a2 | restart:a2 | restart:a2:1(앞 1문장 뒤부터) | phrases | quiz | log | settings`: 시작 화면.
- `SIMCTL_CHILD_LBN_AUTOOPEN=<문장 id>`: 공책을 열자마자 그 항목을 펼친다. `SIMCTL_CHILD_LBN_AUTOVOID=<문장 id>`: 그 문장의 지금 번역을 "잘못 눌렀다"로 표시한 뒤 항목을 펼친다(되살리기 줄 확인용).
- `SIMCTL_CHILD_LBN_AUTOPIN=<문장 id>`: 공책을 열자마자 그 문장의 첫 지적 표현을 표현장에 붙인다("붙여 둠 ✓"·"써 보기" 확인용).
- `SIMCTL_CHILD_LBN_AUTOMERGE=prev|next`: 공책을 열자마자 현재 문장을 그 방향으로 합친다(다시 쓰기 중 합치기 확인용).
- `SIMCTL_CHILD_LBN_SESSION=1`: 공부 세션이 시작된 상태로 시작(모의 서버와 기기 캐시 둘 다 시작점을 가짐. 서버가 null이면 앱이 캐시를 지운다).
- `SIMCTL_CHILD_LBN_AUTOSUBMIT=1|stop`: 공책을 열자마자 현재 문장에 번역을 넣고 제출(채점 중 상태·멈추기 버튼 확인용, 모의 채점이 8초 걸린다. `stop`이면 2초 뒤 멈추기까지).
- `SIMCTL_CHILD_LBN_AUTOANSWER=1|stop`: 응용 탭(`LBN_ROUTE=drills`)에서 첫 문제에 답을 넣고 바로 제출(`stop`이면 2초 뒤 멈추기까지). `SIMCTL_CHILD_LBN_AUTOTRY=<문장 id>`: 그 문장의 첫 붙은 표현으로 써 보기 상자를 열고 문장을 넣어 제출(`LBN_AUTOPIN`·`LBN_AUTOOPEN`과 함께, `LBN_AUTOSTOP=1`이면 2초 뒤 멈추기까지). 둘 다 모의 응용 채점이 8초 걸린다(멈추기 확인용).
- `SIMCTL_CHILD_LBN_AUTOCLOSE=1`: `LBN_SESSION=1 LBN_AUTOSUBMIT=1`과 함께, 그 채점이 끝나면 "오늘 여기까지"까지 누른다(✂ 줄 아래 총평 확인용).
- `SIMCTL_CHILD_LBN_MASTERED=1`: 모의 표현 p1에 습득 완료 도장이 찍힌 상태로 시작. `SIMCTL_CHILD_LBN_SHOWMASTERED=1`: 표현장이 "습득 완료도 보기"로 시작.
- `SIMCTL_CHILD_LBN_AUTOLINK=<문장 id>`: 그 문장의 첫 붙은 표현의 "엮기"를 연다(`LBN_AUTOOPEN`과 함께). `SIMCTL_CHILD_LBN_FLIP=<표현 id>`: 표현장을 그 포스트잇 뒷면이 보이는 채로 시작. 모의 표현 p1은 p2로 엮여 있다.
- `SIMCTL_CHILD_LBN_PHRASETEST=1`: 표현장(`LBN_ROUTE=phrases`)을 열자마자 표현장 시험으로. `SIMCTL_CHILD_LBN_TESTBUCKET=pending|mastered|all`: 묶음. `SIMCTL_CHILD_LBN_TESTANSWER=right|wrong|wrongmark`: 첫 카드에 맞는/틀린 답을 넣고 확인까지(`wrongmark`는 "몰랐다"까지).
- `SIMCTL_CHILD_LBN_TESTMODE=write|meaning|advanced`: 시험 방식. `SIMCTL_CHILD_LBN_TESTLAYOUT=sheet|card`: 시험지/카드(LBN_TESTANSWER가 있으면 카드로). `SIMCTL_CHILD_LBN_SHEETGRADE=1`: 시험지 첫 줄 맞게·둘째 줄 틀리게·나머지 빈칸으로 채워 바로 채점. `SIMCTL_CHILD_LBN_TAPE=1`: 표현장을 열자마자 테이프로, `SIMCTL_CHILD_LBN_TAPEPLAY=1`이면 바로 재생.
- `SIMCTL_CHILD_LBN_RANGE=<from>-<to>`: 시험·테이프 번호 범위를 그 값으로 시작.
- `SIMCTL_CHILD_LBN_AUTOPHRASES=<표현 id>`: 공책을 열고 1초 뒤 그 표현으로 표현장 시트를 연다("표현장 ↗" 확인용).
- `SIMCTL_CHILD_LBN_AUTOSCROLL=1`: 기록 탭(`LBN_ROUTE=log`, 날짜 보기로 연다)을 받은 뒤 맨 아래로 스크롤(세션 총평 줄 확인용). 응용 탭에서는 12초 뒤 StudyDot 패널을 닫고 최근 응용 목록 끝으로(✂ 줄 확인용, `LBN_AUTOANSWER=1 LBN_AUTOCLOSE=1`과 함께). `SIMCTL_CHILD_LBN_BYARTICLE=1`: 모의 세션 닫기 총평에 기사별 총평 둘.
- `SIMCTL_CHILD_LBN_AUTOMARK=1`: 문답의 답에서 두 번째~세 번째 단어를 고른 상태로("밑줄 긋기" 버튼 확인용). 값이 있으면 모의 서버가 s1 구조 상자에 문답 q0을 미리 둔다. `=2`: 바로 "밑줄 긋기"까지 누르고 모의 PUT marks를 8초 늦춘다 → 앱 로그에 "qa marks drawn"이 PUT 200보다 먼저 찍히는지(즉시 그리기 확인용).

- `SIMCTL_CHILD_LBN_AUTOSENTPIN=<문장 id>`: 공책을 열자마자 그 문장 전체를 표현장에 붙인다("문장 붙여 둠 ✓" 확인용).

- `SIMCTL_CHILD_LBN_LOGMODE=article`: 기록 탭(`LBN_ROUTE=log`)을 기사 보기로 연다. `SIMCTL_CHILD_LBN_AUTOREVIEW=1`: 기록 탭 총평 본문을 "자세히" 펼친 채로.

- `SIMCTL_CHILD_LBN_AUTOSTRUCT=<문장 id>`: 그 문장을 펼치자마자 "구조 분석"을 받는다(`LBN_AUTOOPEN`과 함께. 모의 분석은 2.5초 걸린다). `SIMCTL_CHILD_LBN_AUTOASK=<질문>`: 구조 상자가 뜨자마자 그 질문을 보낸다(모의 답은 2초).
